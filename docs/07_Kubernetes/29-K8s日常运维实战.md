```bash

kubectl describe node node1 | grep -A 8 "Allocated resources"

kubectl get node node1 -o jsonpath='{range .status.conditions[*]}{.type}={.status} {end}'

# 排水前检查: 该节点是否有不可容忍的 Pod
kubectl get pods -A -o wide | grep node1

# === 多集群管理 (kubectl context) ===
```

## 二、Pod 生命周期与排障

### 2.1 Pod 生命周期

```
Pod 状态机:

  ┌─────────┐    ┌──────────┐    ┌──────────┐    ┌─────────┐
  │ Pending │───→│ Running  │───→│ Succeeded│    │ Failed  │
  │ (调度)   │    │ (运行中)  │    │ (正常退出)│    │ (异常退出)│
  └────┬────┘    └────┬─────┘    └──────────┘    └─────────┘
       │              │
       │              ├───→ CrashLoopBackOff (反复崩溃)
       │              └───→ Error (容器错误)
       │
       ├──→ ContainerCreating (镜像拉取/存储挂载)
       ├──→ ImagePullBackOff (镜像拉取失败)
       ├──→ CreateContainerError
       └──→ PodInitializing (init 容器)

  状态说明:
    Pending:          已创建, 等待调度
    ContainerCreating: 容器创建中 (拉镜像/挂卷/网络)
    Running:          至少一个容器运行
    CrashLoopBackOff: 容器反复崩溃重启 (最常见问题!)
    ImagePullBackOff: 镜像拉取失败
    Error:            容器异常退出
    Succeeded:        正常完成 (Job)
    Failed:           执行失败 (Job)
    Unknown:          kubelet 失联

  Pod 阶段 (status.phase):
    Pending / Running / Succeeded / Failed / Unknown

  容器状态 (status.containerStatuses[].state):
    Waiting / Running / Terminated

  容器重启原因 (lastState.terminated.reason):
    Error:           程序异常退出
    OOMKilled:       内存超限被杀
    Deadlined:       超过 terminationGracePeriod
    ContainerCannotRun: 环境问题
```

### 2.2 Pod 排障标准流程

```bash
# === 1. 查看 Pod 状态 ===
kubectl get pods -n myapp
# NAME                     READY   STATUS             RESTARTS   AGE
# nginx-7c9f5b7c6f-abcde   1/2     CrashLoopBackOff   5          3m

# === 2. 查看事件 (最重要的第一步!) ===
kubectl describe pod nginx-7c9f5b7c6f-abcde -n myapp
# Events:
#   Type     Reason     Age   From               Message
#   ----     ------     ----  ----               -------
#   Normal   Scheduled  4m    default-scheduler  Successfully assigned...
#   Normal   Pulling    4m    kubelet            Pulling image "nginx:1.25"
#   Normal   Pulled     3m    kubelet            Successfully pulled image
#   Normal   Created    3m    kubelet            Created container nginx
#   Normal   Started    3m    kubelet            Started container nginx
#   Warning  BackOff    1m    kubelet            Back-off restarting failed container

# 只看事件
kubectl get events -n myapp --sort-by=.lastTimestamp | tail -20
kubectl get events -n myapp --field-selector type=Warning

# === 3. 查看日志 ===
# 当前容器
kubectl logs nginx-7c9f5b7c6f-abcde -n myapp

# 上次崩溃的日志 (关键!)
kubectl logs nginx-7c9f5b7c6f-abcde -n myapp --previous
# 或 -p

# 多容器
kubectl logs pod-name -c sidecar -n myapp

# 持续跟踪
kubectl logs -f pod-name -n myapp --tail=100

# 全部容器
kubectl logs pod-name --all-containers=true

# 带时间戳
kubectl logs pod-name --timestamps

# 历史日志 (容器重启过)
kubectl logs pod-name -p --tail=50

# === 4. 查看容器状态详情 ===
kubectl get pod pod-name -n myapp -o yaml | grep -A 30 "status:"

# 容器退出码
kubectl get pod pod-name -n myapp -o jsonpath='{.status.containerStatuses[0].lastState.terminated.exitCode}'

# 退出码速查:
#   0:   正常退出
#   1:   程序错误 (最常见, 查日志)
#   126: 权限/命令错误
#   127: 命令不存在
#   128+n: 被信号终止 (130=SIGINT, 137=SIGKILL/OOM, 143=SIGTERM)

# === 5. 进入容器排查 ===
kubectl exec -it pod-name -n myapp -- /bin/sh
kubectl exec -it pod-name -c container2 -n myapp -- bash

# 容器内排查
# ps aux         查看进程
# netstat -tlnp  查看端口
# curl localhost:8080/health  健康检查
# cat /etc/resolv.conf   DNS
# df -h         磁盘
# free -m       内存

# === 6. 定位节点与资源 ===
kubectl get pod pod-name -n myapp -o wide   # 看 NODE

# 节点上的 kubelet 日志
journalctl -u kubelet -n 100 --no-pager | grep -i error

# CRI 日志 (containerd)
journalctl -u containerd -n 100 --no-pager | grep -i error
crictl ps -a | grep pod-name
crictl logs <container-id>
crictl inspect <container-id>
```

### 2.3 常见 Pod 问题速查

| 现象 | 原因 | 排查 | 解决 |
|:---|:---|:---|:---|
| **ImagePullBackOff** | 镜像不存在/私有仓库认证失败/网络 | `describe` 看事件 | 检查镜像名/`imagePullSecrets`/仓库连通性 |
| **CrashLoopBackOff** | 程序崩溃/配置错误/资源不足 | `logs -p` 看崩溃日志 | 修配置/扩资源/检查入口命令 |
| **Pending** | 资源不足/污点/亲和性不满足 | `describe` 看调度事件 | 扩节点/去污点/改调度策略 |
| **ContainerCreating 卡住** | 存储挂载失败/网络插件异常 | `describe` + 节点日志 | 检查 PVC/CSI/CNI |
| **OOMKilled** | 内存超 limit | `describe` + 看 exitCode 137 | 调 limit/查内存泄漏 |
| **CreateContainerError** | 镜像命令错误/环境变量问题 | `describe` | 检查 command/env |
| **RunContainerError** | 容器运行时错误 | 节点 kubelet 日志 | 检查 containerd |
| **Unknown** | kubelet 失联/节点挂 | 检查节点 | 重启 kubelet/节点 |
| **Evicted** | 节点内存/磁盘压力 | `kubectl get events` | 扩容/清理节点资源 |
| **NodeAffinity 冲突** | 亲和性规则 | `describe` 事件 | 改亲和性 |
| **SchedulingFailed** | 端口冲突/PVC 不匹配 | `describe` | 检查 port/PVC |
| **Liveness 失败重启** | 探针太敏感/应用卡死 | `logs` + 看探针配置 | 调探针参数 |
| **Readiness 失败** | 应用未就绪/依赖服务未起 | `logs` + 检查依赖 | 修应用/调就绪探针 |

### 2.4 探针 (Probe) 配置

```yaml
# probe-example.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: app
        image: myapp:v1.0.0
        ports:
        - containerPort: 8080

        # 就绪探针: 流量入口, 未就绪不接流量
        readinessProbe:
          httpGet:
            path: /health/ready
            port: 8080
          initialDelaySeconds: 5    # 启动后 5s 开始探测
          periodSeconds: 10         # 每 10s 一次
          timeoutSeconds: 3         # 超时 3s
          successThreshold: 1       # 连续 1 次成功
          failureThreshold: 3       # 连续 3 次失败 → 摘流量

        # 存活探针: 死了重启
        livenessProbe:
          httpGet:
            path: /health/live
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 15
          timeoutSeconds: 3
          failureThreshold: 3       # 连续 3 次失败 → 重启容器

        # 启动探针: 慢启动应用用 (1.16+)
        startupProbe:
          httpGet:
            path: /health/startup
            port: 8080
          initialDelaySeconds: 0
          periodSeconds: 5
          failureThreshold: 30      # 最多 150s 等启动

# 探针类型:
#   httpGet:   HTTP GET 请求
#   tcpSocket: TCP 端口探测
#   exec:      执行命令 (exit 0 成功)
```

```bash
# 探针调优经验:
# 1. 慢启动应用 (JVM/大模型): 用 startupProbe 替代加大 initialDelaySeconds
# 2. liveness 要宽松, readiness 要严格
# 3. 不要对依赖服务的健康状态做 liveness 判断 (雪崩)
# 4. HTTP 探针注意: 返回值 2xx/3xx 算成功, 4xx/5xx 失败
# 5. 探针日志: kubectl describe 里能看到 probe 结果
```

## 三、资源管理与配额

### 3.1 requests / limits 原理

```
资源模型:

  requests (请求量):
    - 调度依据: 节点累计 requests <= 节点容量
    - 不限制使用, 只是"预留"
    - 节点超卖: 所有 Pod requests 之和可 > 节点容量 (超卖需谨慎)

  limits (上限):
    - 强制限制
    - CPU: 限制使用 (throttling, 不会杀)
    - 内存: 超限直接 OOMKilled (不可压缩资源)
    - 磁盘 (ephemeral-storage): 超限驱逐 Pod

  QoS 等级 (由 requests/limits 组合决定):

  ┌───────────────────┬───────────┬───────────┬───────────┐
  │ QoS               │ Guaranteed│ Burstable │ BestEffort│
  ├───────────────────┼───────────┼───────────┼───────────┤
  │ requests=limits   │ ✅ 全部容器│ 部分     │ ❌        │
  │ 被杀优先级        │ 最低      │ 中        │ 最高      │
  │ 适用场景          │ 核心稳定   │ 通用      │ 非关键    │
  └───────────────────┴───────────┴───────────┴───────────┘
    内存不足时按 QoS 顺序驱逐: BestEffort > Burstable > Guaranteed

资源单位:
  CPU:
    100m = 0.1 核
    1 = 1 核 (vCPU)
    常见: 100m / 250m / 500m / 1 / 2 / 4

  内存:
    Mi/Gi = 二进制 (1024)
    M/G = 十进制 (1000)
    常见: 128Mi / 256Mi / 512Mi / 1Gi / 2Gi / 4Gi / 8Gi

  存储:
    Ki/Mi/Gi/Ti/Pi/Ei (二进制)
    K/M/G/T/P/E (十进制)
```

```yaml
# resource-example.yaml
apiVersion: apps/v1
kind: Deployment

  name: webapp

  replicas: 3

    spec:
      containers:
```

```yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: limits
  namespace: myapp
spec:
  limits:
  - default:                     # 未声明时的默认 limits
      cpu: 500m

      memory: 128Mi
```

### 3.3 HPA 水平扩缩容

```yaml
# hpa.yaml — 基于 CPU/内存自动扩缩
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: webapp-hpa
  namespace: myapp
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: webapp
  minReplicas: 3
  maxReplicas: 20
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 60      # CPU 利用率 60%
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 70
  behavior:                          # 1.23+ 行为配置
    scaleDown:
      stabilizationWindowSeconds: 300   # 缩容冷却 5 分钟
      policies:
      - type: Percent
        value: 50                       # 最多缩 50%
        periodSeconds: 60
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
      - type: Percent
        value: 100                      # 最多翻倍
        periodSeconds: 60
      - type: Pods
        value: 4                        # 最多 +4
        periodSeconds: 60
```

## 四、网络运维

### 4.1 网络模型

```
K8s 网络模型 (每个 Pod 一个 IP):

  Pod 网络 (CNI):
    - 每个 Pod 独立 IP (集群内互通)
    - CNI: Calico / Cilium / Flannel / Weave
    - 默认不隔离 (Pod 间全互通, 需要 NetworkPolicy)

  Service (负载均衡):
    - ClusterIP:  集群内虚拟 IP
    - NodePort:   节点端口暴露
    - LoadBalancer: 云厂商 LB
    - ExternalName: DNS 别名

  流量路径:

    Client → Ingress → Service(ClusterIP) → Endpoints → Pod
                            ↓
                     kube-proxy (iptables/ipvs)

  DNS:
    CoreDNS: 集群 DNS (10.96.0.10)
    解析规则:
      svc:      myapp.myapp.svc.cluster.local
      pod:      10-244-1-5.myapp.pod.cluster.local

  服务发现:
    - 同命名空间: 直接用服务名 myapp
    - 跨命名空间: myapp.default.svc.cluster.local
    - Headless Service: 返回所有 Pod IP (StatefulSet 用)
```

## 五、存储运维

### 5.1 PV / PVC / StorageClass

```
存储模型:

  StorageClass (动态供给):
    ├─ local-path:    本地目录
    ├─ nfs:           NFS 共享
    ├─ csi-hostpath:  HostPath CSI
    ├─ csi-nfs:       NFS CSI
    ├─ cephfs:        CephFS
    ├─ rbd:           Ceph RBD 块
    ├─ ebs/gp2:       云盘 (AWS/GCP/Azure)
    └─ 自定义 CSI

  PVC → StorageClass → PV (动态创建)

  PV 访问模式:
    ReadWriteOnce (RWO):    单节点读写 (块存储默认)
    ReadOnlyMany (ROX):     多节点只读
    ReadWriteMany (RWX):    多节点读写 (NFS/CephFS)
    ReadWriteOncePod (RWOP): 单 Pod (1.22+)

  回收策略:
    Retain:    保留 (手动处理)
    Delete:    自动删除 (动态供给默认)
    Recycle:   已废弃

  绑定模式:
    Immediate: 立即绑定 (默认)
    WaitForFirstConsumer: 等 Pod 调度 (本地存储必用!)

生命周期:
  Provision (动态创建)
    → Bound (绑定)
    → 使用中 (Pod 挂载)
    → 删除 PVC → PV Released → (Delete 策略) 删除
```

```yaml
# storageclass-local.yaml — 本地存储 (WaitForFirstConsumer 关键!)
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-storage
provisioner: kubernetes.io/no-provisioner
volumeBindingMode: WaitForFirstConsumer
# 无动态供给, 需手动创建 PV

# storageclass-nfs.yaml — NFS 动态供给
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: nfs-csi
provisioner: nfs.csi.k8s.io
parameters:
  server: 10.0.1.50
  share: /data/nfs
reclaimPolicy: Delete
volumeBindingMode: Immediate
mountOptions:
  - hard
  - nfsvers=4.1
```


## 八、备份与恢复

### 8.1 etcd 备份 (最重要!)

```bash
# === etcd 备份 (集群的"唯一真相") ===

# 1. 直接备份 (官方方式)
# 在控制平面节点上
ETCDCTL_API=3 etcdctl \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /backup/etcd-snapshot-$(date +%Y%m%d).db

# 输出
# {"level":"info","ts":"...","caller":"snapshot/v3_snapshot.go:65","msg":"created temporary db file","path":"/backup/etcd-snapshot-20260714.db.part"}
# {"level":"info","ts":"...","caller":"snapshot/v3_snapshot.go:71","msg":"fetching snapshot","endpoint":"https://127.0.0.1:2379"}
# {"level":"info","ts":"...","caller":"snapshot/v3_snapshot.go:80","msg":"Saved and hash verified","path":"/backup/etcd-snapshot-20260714.db"}

# 2. 验证快照
ETCDCTL_API=3 etcdctl --write-out=table snapshot status /backup/etcd-snapshot-20260714.db
# +----------+----------+------------+------------+
# |   HASH   | REVISION | TOTAL KEYS | TOTAL SIZE |
# +----------+----------+------------+------------+
# | 1234abcd |   123456 |      12345 |      45 MB |
# +----------+----------+------------+------------+

# 3. 定时备份 (cron)
cat > /usr/local/bin/etcd-backup.sh << 'EOF'
#!/bin/bash
set -euo pipefail

BACKUP_DIR=/backup/etcd
DATE=$(date +%Y%m%d-%H%M)
KEEP=7

mkdir -p ${BACKUP_DIR}

ETCDCTL_API=3 /usr/bin/etcdctl \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save ${BACKUP_DIR}/etcd-${DATE}.db

# 验证
/usr/bin/etcdctl --write-out=table snapshot status ${BACKUP_DIR}/etcd-${DATE}.db

# 清理
find ${BACKUP_DIR} -name "*.db" -mtime +${KEEP} -delete

# 上传远端
# rclone copy ${BACKUP_DIR}/etcd-${DATE}.db s3://backup/etcd/
EOF
chmod +x /usr/local/bin/etcd-backup.sh

# cron: 0 */4 * * * /usr/local/bin/etcd-backup.sh (每 4 小时)

# 4. etcd 恢复 (灾难场景)
# 停止 kube-apiserver
mv /etc/kubernetes/manifests/kube-apiserver.yaml /tmp/   # 移除静态 Pod

# 停止 etcd
systemctl stop etcd   # 或移除静态 Pod

# 恢复到新数据目录
ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd-20260714.db \
  --data-dir=/var/lib/etcd-restore \
  --initial-cluster=master1=https://10.0.1.10:2380 \
  --initial-advertise-peer-urls=https://10.0.1.10:2380 \
  --initial-cluster-token=etcd-cluster-restore

# 替换数据目录
mv /var/lib/etcd /var/lib/etcd.old
mv /var/lib/etcd-restore /var/lib/etcd
chown -R etcd:etcd /var/lib/etcd

# 启动 etcd, 恢复 apiserver
systemctl start etcd
mv /tmp/kube-apiserver.yaml /etc/kubernetes/manifests/

# 验证
kubectl get nodes
kubectl get pods -A
```

## 十、故障处理

### 10.1 故障速查表

| 故障 | 现象 | 排查 | 解决 |
|:---|:---|:---|:---|
| **节点 NotReady** | `kubectl get nodes` 显示 NotReady | 检查节点: ssh / kubelet / containerd / 磁盘 | 重启 kubelet / 清理磁盘 / 换节点 |
| **磁盘满** | 节点 DiskPressure / Pod Evicted | `df -h` / `/var/lib/docker` 或 containerd 目录 | 清理镜像/日志/旧 Pod |
| **API Server 挂** | kubectl 超时 | 检查 apiserver 静态 Pod / etcd 健康 | 看 etcd, 恢复 etcd |
| **etcd 慢** | API 延迟飙升 | `etcdctl endpoint health` / 磁盘 fsync | 换 SSD / 检查 leader |
| **CoreDNS 故障** | 服务间域名解析失败 | `kubectl get pods -n kube-system -l k8s-app=kube-dns` | 看日志 / 重启 / 检查网络 |
| **Pod 无法调度** | Pending | `describe` 看调度事件 | 资源不足/污点/亲和性 |
| **CrashLoopBackOff** | 容器反复重启 | `logs -p` | 修应用/配置 |
| **OOMKilled** | 内存超限被杀 | `describe` 看 exitCode 137 | 调 limit / 修内存泄漏 |
| **Ingress 502/504** | 网关错误 | 看 Ingress controller 日志 | 后端 Pod 未就绪/超时 |
| **Service 不通** | 访问 ClusterIP 失败 | endpoints / kube-proxy | 查 selector / ipvs |
| **PVC Pending** | 存储无法供给 | `describe pvc` | StorageClass/CSI/容量 |
| **证书过期** | apiserver 日志 TLS 错误 | 查看 /etc/kubernetes/pki | kubeadm 更新证书 |
| **kubelet 证书过期** | 节点无法注册 | `journalctl -u kubelet` | kubeadm certs renew |
| **网络插件异常** | 所有 Pod 网络不通 | calicoctl/cilium status | 重启网络插件 |
| **节点重启后 Pod 不恢复** | Pod 一直 Terminating | 检查 finalizers / 强制删 | force delete |

### 10.2 节点 NotReady 处理

```bash
# === 场景: node1 NotReady ===

# 1. 确认节点状态
kubectl get node node1
# NAME    STATUS     ROLES    AGE   VERSION
# node1   NotReady   <none>   45d   v1.31.1

# 2. SSH 上节点排查
ssh node1

# kubelet 状态
systemctl status kubelet
journalctl -u kubelet -n 50 --no-pager

# 常见原因:
# a) kubelet 挂了 → systemctl restart kubelet
# b) 磁盘满 → df -h; 清理
# c) containerd 挂 → systemctl status containerd
# d) 证书过期 → journalctl 里看到 x509
# e) 网络插件问题 → CNI 状态

# 3. 磁盘清理
df -h
# /var/lib/containerd 满了?
# 清理无用镜像
crictl rmi --prune
# 清理日志
find /var/log -name "*.log" -size +100M -exec truncate -s 0 {} \;
# 清理 containerd 垃圾
crictl rm --prune

# 4. kubelet 证书更新
kubeadm certs renew all   # 控制平面
systemctl restart kubelet

# 5. 恢复后
kubectl uncordon node1
kubectl get node node1
```

### 10.4 DNS 故障排查

```bash

# 1. 测试 DNS

kubectl exec -it pod-name -- nslookup myapp.default.svc.cluster.local

# 2. CoreDNS 状态

kubectl logs -n kube-system coredns-xxxx -f

# 3. 常见原因:
# a) CoreDNS 副本数不够 → scale
kubectl scale deploy coredns -n kube-system --replicas=3

# b) CoreDNS 自身 DNS 上游问题 (forward)
#   检查 Corefile: .:53 { forward . /etc/resolv.conf }
#   节点 /etc/resolv.conf 需可达

# c) 网络策略阻挡 53 端口

# d) 大量查询 → 调缓存
# Corefile 加:
#   cache {
#       success 9984 30
#       denial 9984 5
#   }

# 4. Pod 内 /etc/resolv.conf 检查
# nameserver 10.96.0.10 (Service 网络)
# search default.svc.cluster.local svc.cluster.local cluster.local
# options ndots:5
```

### 11.2 命名空间资源报告

```bash
#!/bin/bash
# k8s-report.sh — 资源使用报告
# 输出各命名空间资源使用情况

echo "命名空间资源概览:"
echo "=================="

for ns in $(kubectl get ns -o jsonpath='{.items[*].metadata.name}' | tr ' ' '\n' | grep -v kube-); do
  echo
  echo "--- ${ns} ---"
  
  # 资源请求量
  REQ_CPU=$(kubectl get pods -n ${ns} -o json | jq '[.items[].spec.containers[].resources.requests.cpu // "0"] | map(if type=="string" then (if endswith("m") then .[0:-1]|tonumber/1000 else .|tonumber end) else . end) | add // 0' 2>/dev/null)
  REQ_MEM=$(kubectl get pods -n ${ns} -o json | jq '[.items[].spec.containers[].resources.requests.memory // "0"] | map(if type=="string" then (if endswith("Gi") then .[0:-2]|tonumber*1024 elif endswith("Mi") then .[0:-2]|tonumber/1024 else .|tonumber end) else . end) | add // 0' 2>/dev/null)
  
  PENDING=$(kubectl get pods -n ${ns} --field-selector status.phase=Pending 2>/dev/null | wc -l)
  
  echo "  Pod 数:      $(kubectl get pods -n ${ns} --no-headers 2>/dev/null | wc -l)"
  echo "  Pending:     ${PENDING}"
  echo "  requests.cpu: ${REQ_CPU} 核"
  echo "  requests.mem: ${REQ_MEM} Gi"
done
```

### 12.2 PDB 与优雅停机

```yaml
# pdb.yaml — PodDisruptionBudget (关键服务必配!)
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: myapp-pdb
  namespace: myapp
spec:
  minAvailable: 2        # 最少 2 个可用
  # 或 maxUnavailable: 1
  selector:
    matchLabels:
      app: myapp
```

```yaml
# 优雅停机配置
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  template:
    spec:
      terminationGracePeriodSeconds: 60   # 宽限期
      containers:
      - name: app
        image: myapp:v1
        lifecycle:
          preStop:
            exec:
              command: ["/bin/sh", "-c", "sleep 10"]   # 先等流量摘除
```
